# DMCコンバーター 設計

WAVなどの音声ファイルから、APUのDMC（DPCM）チャンネルで鳴らすサンプル（`.dmc`）を作るツールの設計です。
DMCチャンネルの実装（APU・曲データ・再生・トラッカー）は複数の段階に分けて進めます。この文書はその1段目で、変換ツールを中心に、後の段階とのつながりを決めます。

## 目的と範囲

- WAV（と、miniaudio が読める FLAC / MP3）を、DMCのビット列（`.dmc`）に変換する。
- `.dmc` は先頭から生のビット列だけを並べたファイルにする（FamiTracker の `.dmc` と同じ）。FamiTracker や既存の素材と行き来できる。
- 変換結果を耳で確かめるため、`.dmc` をWAVに戻すプレビューも出力できるようにする。
- 変換処理の本体はエンジンに置き、コマンドラインツールとトラッカー（後の段階でのWAVの読み込み）で共有する。

範囲外: PAL のレート、NSF の書き出し、DMCのIRQ（曲の再生には使わない）。

## DMCの仕様（変換で守ること）

変換の出力は、APUの DMC の動きにそのまま合わせる必要があります（参考: [nesdev wiki: APU DMC](https://www.nesdev.org/wiki/APU_DMC)）。

### 出力レベル

- 出力は7bitのレベル（0〜127）。`$4011` で直接設定できる。
- 1bitごとに、`1` なら +2、`0` なら −2 する。ただし範囲を超える場合は変えない（`1` でレベルが126以上、`0` でレベルが1以下のとき）。
- 1バイトの中では **下位ビットから** 使う。

変換器はこの規則でAPUを真似しながら1bitずつ決めます。規則はエンジンの1つの関数（`stepDpcmLevel()`、[後述](#エンジン側のapi)）にまとめ、変換器とAPUの `DmcChannel` の両方がそれを使います。こうすると、変換器が想定した波形とAPUが鳴らす波形が必ず一致します。

### レート（NTSC）

`$4010` の下位4bitで選ぶ、16段階の固定レートです。周波数は CPU クロック（1,789,773Hz）を周期で割った値です。

| レート | 周期（CPUサイクル/bit） | 周波数（Hz） | 4081バイトの長さ |
| --- | --- | --- | --- |
| 0 | 428 | 4181.7 | 7.81秒 |
| 1 | 380 | 4709.9 | 6.93秒 |
| 2 | 340 | 5264.0 | 6.20秒 |
| 3 | 320 | 5593.0 | 5.84秒 |
| 4 | 286 | 6257.9 | 5.22秒 |
| 5 | 254 | 7046.3 | 4.63秒 |
| 6 | 226 | 7919.4 | 4.12秒 |
| 7 | 214 | 8363.4 | 3.90秒 |
| 8 | 190 | 9419.9 | 3.47秒 |
| 9 | 160 | 11186.1 | 2.92秒 |
| 10 | 142 | 12604.0 | 2.59秒 |
| 11 | 128 | 13982.6 | 2.33秒 |
| 12 | 106 | 16884.6 | 1.93秒 |
| 13 | 84 | 21306.8 | 1.53秒 |
| 14 | 72 | 24858.0 | 1.31秒 |
| 15 | 54 | 33143.9 | 0.99秒 |

### 長さとアドレス

- 長さは `$4013` で `L × 16 + 1` バイト（L = 0〜255）。1サンプルは **1〜4081バイト** で、長さは必ず `16n + 1` バイト。
- 開始アドレスは `$4012` で `$C000 + A × 64`。サンプルは64バイト境界に置く必要がある。DMCが読めるのは `$C000`〜`$FFFF` の16KB。

変換器は長さを `16n + 1` に切り上げ、余りを `1` と `0` が交互のビットで埋めます。交互のビットなら、レベルは最後の値の±2の範囲にとどまります。
アドレスは変換器では扱わず、再生側（`SongPlayer`）が曲を読み込むときに割り当てます（[後述](#後の段階とのつながり)）。

### 傾きの限界（音量の決め方に効く）

1bitで±2しか動けないので、大きく速い波形は追いつけずに歪みます（スロープオーバーロード）。
振幅 A レベル・周波数 f の正弦波が追いつける条件は `2π·f·A ≤ 2 × レート周波数` です。

| レート | 振幅63（最大） | 振幅32 | 振幅16 |
| --- | --- | --- | --- |
| 15（33.1kHz） | 167Hz まで | 330Hz まで | 659Hz まで |
| 9（11.2kHz） | 57Hz まで | 111Hz まで | 223Hz まで |

つまり「ピークで正規化して最大音量」は、低音以外では歪みます。キックやベースは大きく、スネアや声は小さめ・高いレートにするのが基本です。
変換器は、追いつけなかったbitの割合（`overload`）を表示して、音量やレートを決める手がかりにします。

### 他のチャンネルへの影響

APUのミキサーでは、Triangle・Noise・DMC が非線形に合成されます。DMCのレベルが高いほど、Triangle と Noise の音が小さくなります。
このため、サンプルが鳴り終わったときのレベル（休止レベル）は曲全体の音量に影響します。変換器は、終わりに休止レベルまで戻す処理を入れます（[変換の手順](#変換の手順) 6）。

```
  main.cpp                                      引数の解析、ファイルの読み書き、結果の表示
  CMakeLists.txt
```

- 変換の本体（`encodeDpcm()`）は、float のモノラル波形とサンプルレートを受け取り、バイト列を返すだけの関数にします。ファイルの読み書きは持たないので、単体テストしやすく、トラッカーからも同じものを呼べます。
- 音声ファイルの読み込みは、ツール側で miniaudio の `ma_decoder` を直接使います（エンジンの `AudioDecoder` は `engine/src` の内部用なので）。CMake の `miniaudio` ターゲットにリンクします。
  - ファイルは `std::filesystem::path` で読んでから `ma_decoder_init_memory()` に渡します。日本語のファイル名でも開けるようにするためです。
- プレビューのWAV（16bitモノラル）は、ヘッダーが単純なのでツールで直接書きます。
- `ocf_dmcconv` は ImGui を使わないので、`OCF_ENABLE_IMGUI` に関係なくビルドします。

## 変換の手順

```
入力ファイル ─ 1.読み込み ─ 2.モノラル化 ─ 3.無音のトリム ─ 4.音量 ─ 5.リサンプル ─ 6.ビット列の決定 ─ 7.長さの調整 ─ .dmc
                                                                                         └─ decodeDpcm() ─ プレビューWAV・誤差の計算
```

1. **読み込み**: `ma_decoder` で float32 に変換して読む。サンプルレートは元のまま。
2. **モノラル化**: 全チャンネルの平均（`ma_decoder` の出力チャンネル数を1にして任せる）。
3. **無音のトリム**（`--trim`）: 前後の、しきい値（既定 −50dBFS）以下の部分を削る。前に無音があると、発音が遅れて聞こえるため。
4. **音量**: `--normalize` ならピークを1.0にそろえてから、`--gain` を掛ける。1.0 がレベルの振幅63に当たる。
5. **リサンプル**: 選んだレートの周波数に変換する。折り返し雑音を防ぐため、窓関数付きsinc（カットオフはレート周波数の0.45倍）で低域通過してから間引く。
   - 自前で実装する。結果がプラットフォームによらず同じになり、テストで値を固定できるため。
6. **ビット列の決定**: 目標レベル `t[i] = center + x[i] × 63`（0〜127に丸める）に対して、休止レベルから始めてビット列を決める。`--method` で方法を選ぶ。
   - `optimal`（既定）: **ビタビ法**。レベル（0〜127の128状態）を状態にして、サンプル全体の二乗誤差が最小になるビット列を求める。計算量は「ビット数 × 128 × 2」で、最長の4081バイトでも一瞬で終わる。
   - `greedy`: **貪欲法**。1bitずつ、目標に近づくほうを選ぶ（同じなら前のbitの反対にしてレベルを保つ）。FamiTracker の変換と同じ考え方。
   - 傾きの限界に収まる波形では、どちらもほぼ同じ結果になる（誤差は±2の量子化で決まるため）。限界を超える波形では `optimal` のほうがSNRが1〜3dB高い（試した素材で）。
   - 最後に、レベルを休止レベル（`--rest`、既定は `center`）まで±2ずつ戻すbitを足す。休止レベルから始めるのでレベルの偶奇は休止レベルと同じで、ちょうど戻れる。最大でも64bitなので、長さへの影響は小さい。`--no-return` で省く。
7. **長さの調整**: バイトにまとめ（下位ビットから）、`16n + 1` バイトまで交互のビットで埋める。
   - 4081バイトを超えるときは、既定ではエラーにして、入るレートを表示する。`--truncate` を付けると切り詰め、最後の部分で休止レベルに戻す。切り詰めるときは、使う部分だけをリサンプルする。
   - `--rate auto` では、4081バイトに入る一番高いレートを選ぶ。どのレートにも入らなければエラー（`--truncate` があればレート0で切り詰める）。

変換の後、`decodeDpcm()` で出力を波形に戻し、目標の波形と比べて次を表示します。

- SNR（dB）: 目標の波形と、戻した波形の誤差
- overload: 目標から2レベル（1bit分）より離れたbitの割合。傾きの限界を超えて追いつけなかった部分

## コマンドライン

```
ocf_dmcconv <入力> [<入力> ...] [オプション]
```

| オプション | 既定 | 内容 |
| --- | --- | --- |
| `-o, --output <パス>` | 入力と同じ名前の `.dmc` | 出力先。入力が複数のときはフォルダ |
| `-r, --rate <0-15 \| auto>` | `15` | レート |
| `--normalize` | オフ | ピークを1.0にそろえる |
| `-g, --gain <倍率 \| NdB>` | `1.0` | 音量。`0.5` や `-6dB` |
| `--trim [dBFS]` | オフ（−50） | 前後の無音を削る |
| `--center <0-127>` | `64` | 波形の中心のレベル |
| `--rest <0-127>` | `center` と同じ | 開始と終了のレベル。再生側はサンプルの開始時に `$4011` にこの値を書く |
| `--no-return` | オフ | 終わりに休止レベルへ戻さない |
| `--method <optimal \| greedy>` | `optimal` | ビット列の決め方 |
| `--truncate` | オフ | 4081バイトを超えたら切り詰める |
| `-p, --preview <パス>` | なし | 変換結果を44.1kHzのWAVに戻して書き出す |
| `-q, --quiet` | オフ | 結果の表を出さない |
| `-h, --help` | | 使い方を表示する |

出力の例（合成したキック・スネアと、2秒の220Hzの音）:

```
> ocf_dmcconv kick.wav snare.wav tone_long.wav -r auto --normalize --trim -p preview/
kick.wav -> kick.dmc  rate 15 (33143.9Hz)  1665 bytes  0.40s  SNR 24.3dB  overload 0.0%
snare.wav -> snare.dmc  rate 15 (33143.9Hz)  1249 bytes  0.30s  SNR 3.3dB  overload 27.1%
tone_long.wav -> tone_long.dmc  rate 11 (13982.6Hz)  3505 bytes  2.01s  SNR 4.5dB  overload 97.0%
```

`tone_long` は、最大音量の220Hzがレート11の傾きの限界（振幅63で70Hz）を大きく超えているので、ほとんど追いつけていません。音量を下げるか、短くして高いレートにします。

- 失敗したファイルがあれば、ほかのファイルの変換は続け、終了コードを1にする。引数の誤りは終了コード2。
- `.dmc` は生のビット列だけで、レートも休止レベルも入らない。これは FamiTracker の `.dmc` と互換にするため。必要な情報（レート・休止レベル）は、表示を見てトラッカー側で設定する。トラッカーでWAVを直接読み込む場合は、変換の設定ごと曲に保存する（[後述](#後の段階とのつながり)）。

## エンジン側のAPI

| ヘッダー | 内容 |
| --- | --- |
| [Dpcm.h](../engine/include/ocf/audio/tracker/Dpcm.h) | 定数（レート表、`DPCM_MAX_SAMPLE_BYTES`、`DPCM_MEMORY_SIZE` など）、`getDpcmRateFrequency()`、`getDpcmPlayableLength()`、`stepDpcmLevel()`、`decodeDpcm()` |
| [DpcmEncoder.h](../engine/include/ocf/audio/tracker/DpcmEncoder.h) | `encodeDpcm()` と、その設定 `DpcmEncodeOptions`・結果 `DpcmEncodeResult` |

```cpp
/** One bit of the output unit, as the APU does it: +2 for 1, -2 for 0, unchanged at the limits. */
constexpr uint8_t stepDpcmLevel(uint8_t level, bool bit);

/** Converts mono samples (-1.0 to 1.0) at the sample rate. */
Result<DpcmEncodeResult, std::string> encodeDpcm(std::span<const float> samples, uint32_t sampleRate,
                                                 const DpcmEncodeOptions& options);
```

- `DpcmEncodeOptions` の各項目は、コマンドラインのオプションと1対1に対応する。既定値も同じ。
- エラーは `loadSong()` と同じく `Result<..., std::string>` で返す（空の入力、無音の入力、長すぎる入力、範囲外の設定など）。
- 途中の段階（`findNonSilentRange()`、`resample()`、`encodeBits()`、`packBits()`）は、テストのために `detail` 名前空間で公開している。

## テスト

`engine/test/test_dpcm.cpp`（gtest）で確かめていること:

- `stepDpcmLevel()`: +2/−2、上下の端（0, 1, 126, 127）で変わらないこと。
- `decodeDpcm()`: 下位ビットから読むこと（`0x01` は最初のbitだけ `1`）。
- `getDpcmPlayableLength()`: 1→1、2→17、17→17、18→33、4081→4081。
- `encodeDpcm()`:
  - 出力の長さが必ず `16n + 1` で、4081以下。
  - 無音を変換すると、レベルが休止レベルの±2にとどまる。
  - 傾きの限界に収まる正弦波（レート15、振幅32、100Hz）を変換して戻すと、SNR が20dBを超え、overload が0。
  - 限界を超える正弦波で、`optimal` の SNR が `greedy` 以上。
  - リサンプルで、低い周波数はそのまま残り、ナイキスト周波数より上は消える（折り返さない）。
  - トリムで短くなり、正規化で全体の範囲を使う。
  - `returnToRest` のとき、最後のレベルが休止レベルの±2。
  - 4081バイトを超える入力は、`truncate` なしならエラー、ありなら4081バイト。
  - `rate = nullopt` で、入る一番高いレートを選ぶ。
- 後の段階（4）で、APUの `DmcChannel` に変換結果を鳴らさせ、出力レベルの列が `decodeDpcm()` と一致することを確かめる（変換器とAPUのずれを防ぐテスト）。

## 後の段階とのつながり

変換ツールの設計に影響するところだけを決めておきます。詳細はそれぞれの段階で設計します。

### APU（`engine/src/audio/apu/DmcChannel`）

- `$4010`（IRQ・ループ・レート）、`$4011`（レベルの直接設定）、`$4012`（アドレス）、`$4013`（長さ）と、`$4015` のbit4（開始・停止、残りバイトの有無）を実装する。
- サンプルのメモリは、APUに16KBのバッファ（`$C000`〜`$FFFF`）として渡す（`Apu::setDmcMemory(std::span<const uint8_t>)`）。CPUがないので、メモリ読み出しによるCPUの停止は真似しない。
- 出力レベルの更新には `stepDpcmLevel()` を使う。
- `Apu::getOutput()` の `dmc` に出力レベルを入れる（ミキサーの式はすでにDMCを含んでいる）。

### 曲データ（`docs/tracker-format.md`）

サンプルは曲のJSONに埋め込みます。ゲームは曲のファイル1つを読めば鳴らせます。

```json
"dpcmSamples": [
  { "index": 0, "name": "Kick", "data": "<base64>", "rate": 15, "restLevel": 64 }
]
```

- `data` は `.dmc` と同じバイト列のbase64。
- `rate` と `restLevel` は変換したときの値で、キーに割り当てるときの初期値になる（再生時のレートはインストゥルメントのキー割り当てで決まる）。
- DPCMのインストゥルメントは、FamiTracker と同じく「ノート → サンプル・レート・ループ・開始レベル」の割り当て表にする。
- `SongPlayer` は `setSong()` のときにサンプルを64バイト境界で16KBに並べ、ノートごとに `$4010`〜`$4013` と `$4015` を書く。

### トラッカー

- `DPCM Samples` ウィンドウ: サンプルの一覧、WAV・`.dmc` の読み込み（WAVは `encodeDpcm()` で変換し、設定を変えて変換し直せる）、`.dmc` の書き出し、波形の表示、試聴。
- インストゥルメントにDPCMのキー割り当てを追加する。

## 決めたこと

設計のときに挙げた選択肢と、選んだ案です（すべておすすめの案にしました）。

| 項目 | 案 | 選んだ案 |
| --- | --- | --- |
| サンプルのメモリの上限 | A: 実機と同じ16KB（`$C000`〜`$FFFF`）に収める / B: 上限なし（アドレスを仮想化） | **A**。`$4012`・`$4013` の意味をそのまま保てて、APUの実装が実機どおりになる。16KBはレート15で約4秒分 |
| サンプルの保存場所 | A: 曲のJSONに埋め込む / B: `.dmc` ファイルを相対パスで参照する | **A**。曲が1ファイルで完結し、ゲームの読み込みもアセットのパスの管理も今のまま |
| 変換を呼べる場所 | A: コマンドラインとトラッカーの両方（本体を共有） / B: コマンドラインだけ | **A**。曲づくりの途中で音量やレートを試すにはトラッカーで変換し直せるほうが速い。本体を共有するので追加の手間は小さい |
| 休止レベルの既定値 | A: 64（波形の中心） / B: 0（Triangle・Noise が最も大きく鳴る） | **A**。0にすると波形の下半分が切れるか、毎回0から中心まで上がる音が入る。曲ごとに変えたいときは `--rest` で変える |

## 実装の順番

| 段階 | 内容 | 状況 |
| --- | --- | --- |
| 1 | `Dpcm.h` と `DpcmEncoder` と、そのテスト | 済み |
| 2 | `ocf_dmcconv`（`--preview` まで） | 済み |
| 3 | `--method optimal`、`--rate auto`、`--trim` | 済み |
| 4 | APU の `DmcChannel` と、変換器とのずれを防ぐテスト | |
| 5 | 曲データと `SongPlayer` | |
| 6 | トラッカーの `DPCM Samples` ウィンドウとキー割り当て | |

設計のときの `--lookahead N`（先のNbitを総当たりする）は、ビタビ法の `--method optimal` に置き換えました。ビタビ法はサンプル全体で誤差が最小になり、計算量もNに対して指数的に増えないためです。
